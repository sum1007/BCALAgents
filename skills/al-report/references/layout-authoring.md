# Report Layout Authoring — Technical Specification (`@bc-report-layout`)

This reference is used exclusively by **BC Report Layout Assistant** in Step 2 (after **BC Report Logic Assistant** has compiled the `.al` object and emitted the schema-valid layout file on disk).

## 1. Automated Layout Population (`scripts/author_layout.py`)

Instead of leaving a blank layout file for the human developer to build from scratch, run:

```bash
python skills/al-report/scripts/author_layout.py --layout "./src/Reports/<FileName>.docx" --title "<Report Title>"
```

The script supports both `.docx` (Word) and `.rdl` (RDLC) files generated by the Business Central compiler:
- **For `.docx`**:
  1. Reads `customXml/item1.xml` to discover the exact XML namespace (`xmlns="urn:microsoft-dynamics-nav/reports/..."`), all `<Labels>`, parent `<DataItems>`, child repeating `<DataItems>`, and their field names.
  2. Reads `customXml/itemProps1.xml` to extract `ds:itemID` (the GUID required by `w:storeItemID`).
  3. Builds a formatted A4 `word/document.xml` containing:
     - Company Header block + Report Title bound to `<Labels>`
     - Parent metadata block (e.g., Customer No., Name, Filter string)
     - A bordered, header-shaded Word Table (`w:tbl`) with a `w15:repeatingSection` Content Control (`w:sdt`) wrapping the detail row `<w:tr>`, and plain-text `<w:sdt>` controls with `<w:dataBinding>` inside each cell
     - A bold Totals row at the bottom of the table (if `Total*` fields exist on the parent dataitem)
     - A 2-column Signature block at the bottom
  4. Writes the updated `word/document.xml` back into the `.docx` archive while keeping `customXml/*` 100% untouched.

- **For `.rdl`**:
  1. Parses the compiler-generated `<DataSets>` and `<ReportParameters>` in the `.rdl` file.
  2. Keeps `<DataSources>`, `<DataSets>`, and `<ReportParameters>` 100% untouched.
  3. Replaces the empty `<Body>` / `<ReportSections>` with an A4 `<PageHeader>`, a complete `<Tablix>` containing header cells and `=Fields!<FieldName>.Value` detail cells, and a `<PageFooter>` with page numbering.

## 2. Manual XML Rules (When Customizing Layouts Further)

### Word OpenXML (`word/document.xml`)
- **Single Field Binding**:
  ```xml
  <w:sdt>
    <w:sdtPr>
      <w:alias w:val="CustomerNo"/>
      <w:tag w:val="CustomerNo"/>
      <w:dataBinding w:prefixMappings="xmlns:ns0='urn:microsoft-dynamics-nav/reports/VASCustomerStatement/50135'"
                     w:xpath="/ns0:ReportDataSet[1]/ns0:DataItems[1]/ns0:Customer[1]/ns0:CustomerNo[1]"
                     w:storeItemID="{GUID-FROM-ITEMPROPS1}"/>
      <w:text/>
    </w:sdtPr>
    <w:sdtContent>
      <w:p><w:r><w:t>[CustomerNo]</w:t></w:r></w:p>
    </w:sdtContent>
  </w:sdt>
  ```
- **Repeating Table Row (`w15:repeatingSection`)**:
  Wrap the `<w:tr>` inside an `<w:sdt>` whose `w:xpath` points to the repeating DataItem node (e.g. `/ns0:ReportDataSet[1]/ns0:DataItems[1]/ns0:Customer[1]/ns0:CustLedgerEntry[1]`) and include `<w15:repeatingSection/>` inside `<w:sdtPr>`.

### System Dataitems (BC v26 / 2025 Wave 1+)
Word and Excel layouts in BC v26+ automatically expose `ReportMetadata` (`ReportName`, `ExtensionName`, `ReportID`) and `ReportRequest` in the XML Mapping pane without adding them to the AL `dataset`.

### ReportExtension Post-Deploy Requirement
A layout packaged in a `reportextension` is NOT activated automatically on deploy. Always instruct the user to open **Report Layout Selection** in Business Central and select the new layout from **Custom Layout Description**.
